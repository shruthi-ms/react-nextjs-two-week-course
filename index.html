Preface: how to study this course

Dear student,

Most people learn React backwards. They memorise useEffect syntax before they understand what a render is, and they learn Next.js caching flags before they understand where code runs. Then an interviewer asks "why does this log the old value?" and the whole structure wobbles.

We will do it the other way round. Every day starts with a mental model, then the syntax, then a lab where you build something, and finally an interview corner where you test whether the model really stuck. If you understand the model, the syntax becomes obvious. If you only know the syntax, every new API feels like magic.

Memory hook — the study loop

Read → Type → Break → Explain → Recall. Read the concept. Type the code yourself (never copy-paste the first time). Break it on purpose and watch the error. Explain it aloud as if to a junior. Recall it the next morning using the interview questions, before reading the answers.

Think of it like

Interview corner

What is the difference between var, let and const?

var is function-scoped and hoisted with value undefined. let and const are block-scoped and sit in the "temporal dead zone" until declared, so using them early throws. const cannot be reassigned, but the object it points to can still be mutated.

What is a closure? Give a practical use.

A function together with the variables from the scope where it was created. Uses: private state (the counter above), function factories, memoisation, and every React event handler that reads props or state.

Shallow copy vs deep copy?

A shallow copy ({...obj}, [...arr]) copies the top level only; nested objects are shared. A deep copy (structuredClone) duplicates every level. React state updates usually need shallow copies of each level you change, not a full deep copy.

== vs ===?

== coerces types before comparing ('1' == 1 is true); === does not. Use === always. React itself uses Object.is, which is like === except NaN equals NaN and +0 differs from -0.

How do arrow functions differ from regular functions?

No own this (they use the surrounding one), no arguments object, cannot be used with new, and support implicit return.

Day 2 · Thinking in React: JSX, components, purity

Week 1 · Foundations

About 3 hours. Today is about the mental model. Do not rush it.

By the end of today you can
  • Explain declarative UI, the virtual DOM and reconciliation in your own words.
  • Write JSX correctly and know what it compiles to.
  • Break a design into a tree of pure components.

2.1 What React actually is

React is a library for building user interfaces out of components. It does one job: given your data, keep the screen in sync with it. Routing, data fetching and server rendering are left to frameworks such as Next.js (Week 2).

Memory hook — the most important equation in this course

UI = f(state). The screen is a function of your data. You change the data; React recomputes the function and updates the screen.

Imperative vs declarative

Think of it like

Imperative is giving a taxi driver every turn. Declarative is telling the driver the destination. React is the driver who knows the roads (the DOM) and finds the shortest route.

2.2 The virtual DOM and reconciliation

Touching the real DOM is comparatively slow. So React keeps a lightweight description of the UI in plain JavaScript objects (often called the virtual DOM). When state changes, React builds a new description, compares it with the previous one (this comparison is reconciliation, or "diffing"), and applies only the differences to the real DOM.

Think of it like

An architect holds the old blueprint and the new blueprint side by side, circles only what changed, and hands the builders a short list. Nobody demolishes the house to move a window.

Jargon buster

Element: a plain object describing what to show ({ type: 'h1', props: {...} }). Component: a function that returns elements. Render: React calling your component function. Commit: React applying the changes to the real DOM.

2.3 Create your first project

StrictMode is a development-only helper. It deliberately renders components twice and runs effects twice to expose impure code and missing clean-ups. It does nothing in production.

2.4 JSX is JavaScript wearing HTML clothes

The six rules of JSX

Memory hook

Curly braces open a window into JavaScript. Anything that produces a value can go through the window; statements (if, for) cannot.

2.5 Components

A component is a JavaScript function that returns JSX. Its name must start with a capital letter: <profile /> would be treated as an unknown HTML tag, <Profile /> as your component.

Common trap — defining components inside components

Never declare function Avatar() inside Profile. A new function is created on every render, so React sees a "different" component type each time and throws away its state. Always declare components at the top level of a module.

2.6 Purity: components are recipes

Think of it like

A recipe. Given the same ingredients, it produces the same dish, and reading the recipe does not set the kitchen on fire. React may "read" your recipe any number of times, in any order, so it must be safe to do so. Side effects (network calls, timers, DOM changes) belong in event handlers or effects, never in the render body.

2.7 "Thinking in React" in five steps

  1. Break the UI into a component hierarchy. Draw boxes on the design. One box, one job.
  2. Build a static version with props only, no state.
  3. Find the minimal state. If it can be computed from something else, it is not state.
  4. Decide where state lives: the closest common parent of everyone who needs it.
  5. Add inverse data flow: children call functions passed down by parents.

Interview corner

What is the virtual DOM and why does React use it?

An in-memory tree of plain objects describing the UI. On each update React builds a new tree, diffs it against the old one, and applies the minimum set of real DOM operations. The win is not that the virtual DOM is "fast", but that it lets you write declarative code while React handles efficient updates.

What is reconciliation?

The algorithm React uses to compare two element trees. Its key assumptions: elements of different types produce different trees (so React replaces them), and key props identify which children are the same across renders.

Is JSX required? What does it compile to?

No. JSX is syntax sugar for function calls (jsx() from react/jsx-runtime, historically React.createElement) that return element objects. A compiler such as Babel, SWC or esbuild does the transformation.

Why must component names start with a capital letter?

JSX treats lowercase tags as built-in HTML elements (strings) and capitalised tags as variables referring to components.

Library vs framework — which is React?

React is a library: you call it, and you choose the router, data layer and build tool. A framework (Next.js) calls your code and provides those decisions for you. Memory aid: you call a library; a framework calls you.

What does StrictMode do?

In development only: double-invokes component bodies, initialisers and effects (mount → unmount → mount) and warns about deprecated APIs, to surface impure renders and missing clean-ups.

Day 3 · Props, children, conditionals, lists & keys

Week 1 · Foundations

About 3 hours. Data flows down; today you learn the pipes.

By the end of today you can
  • Pass data and functions into components and compose layouts with children.
  • Render conditionally without the "stray 0" bug.
  • Render lists with correct keys and explain why keys exist.

3.1 Props are function arguments

Think of it like

Props are a sealed parcel delivered to a component. It may open the parcel and use what is inside, but it must not rewrite the label. Props are read-only. To change what is shown, the parent sends a new parcel.

Memory hook

Props flow down, events flow up. This is "one-way data flow".

3.2 children and composition

React favours composition over inheritance. You never write class SpecialCard extends Card; you build Card with slots (children, or named props like header and footer) and fill them.

3.3 Passing functions down (so children can talk up)

Naming convention: the prop is onSomething, the function that handles it is handleSomething.

3.4 Conditional rendering

Common trap — the stray zero

React renders the number 0 but skips false, null and undefined. Always put a boolean on the left of &&.

3.5 Lists and keys

A key tells React which item is which between renders. With keys, React can move, insert and delete items correctly and keep each item's internal state attached to the right item.

Memory hook

Keys are name tags, not seat numbers. If people change seats, name tags still identify them; seat numbers (array indexes) do not.

See the index-key bug with your own eyes

Rules for keys: unique among siblings (not globally), stable across renders, and never generated during render (Math.random() or crypto.randomUUID() inside map creates new keys every time and destroys state). An index is acceptable only when the list is static: never reordered, filtered, or inserted into, and items hold no state.

Jargon buster

Prop drilling: passing a prop through several layers of components that do not use it, just to reach a deep child. Annoying at three levels, painful at six. Day 6 fixes it with Context.

Interview corner

Props vs state?

Props are inputs passed by the parent and are read-only inside the component. State is data the component owns and can change over time with a setter, causing a re-render. A value can be state in a parent and a prop in its child.

Why does React need keys? What happens with index keys?

Keys let reconciliation match old and new children by identity rather than position. With index keys, removing or reordering items shifts identities, so DOM state (inputs, focus) and component state attach to the wrong item, and React does extra work.

Can a child component modify its props?

No. Props are read-only. The child asks the parent to change data by calling a callback prop; the parent updates its state and re-renders the child with new props.

What is the children prop?

Whatever JSX is nested between a component's opening and closing tags. It enables wrapper components (layouts, cards, modals) and is the basis of composition.

What is prop drilling and how do you avoid it?

Passing props through intermediate components that do not need them. Fixes: composition (pass components as children so the data does not travel), Context, or a state library.

Day 4 · State, events, immutability & forms

Week 1 · Foundations

About 4 hours. The single most important day of Week 1.

By the end of today you can
  • Explain why state exists and why it behaves like a snapshot.
  • Update arrays and objects immutably.
  • Build controlled forms and lift state up to share it.

4.1 Why a normal variable is not enough

Two reasons. A local variable is re-created on every render (it does not persist), and changing it does not tell React to render again. State solves both.

Memory hook

State is a component's memory. Setting state is ringing the doorbell — it asks React to come back and render again.

4.2 Events

React wraps native events in synthetic events with the same interface across browsers. e.stopPropagation() stops bubbling to parents; e.preventDefault() stops the browser's default action.

4.3 State is a snapshot

Think of it like

Each render is a photograph. Inside an event handler you are looking at the photo; calling setCount does not change the photo, it orders a new one. The updater form c => c + 1 says "whatever the latest value is, add one", so the orders queue up correctly.

Batching: React groups all state updates from one event (and, since React 18, from timeouts and promises too) into a single re-render. That is why three calls produce one render.

Memory hook

If the next state depends on the previous state, pass a function.

4.4 Immutability: copy, change, commit

React decides whether something changed by comparing references (Object.is). If you mutate an array and set the same array back, React sees the same reference and may skip the render. So we always create a new array or object.

4.5 Controlled forms

A controlled input gets its value from state and reports every keystroke back through onChange. React is the single source of truth.

Uncontrolled inputs keep their own value in the DOM; you read it when needed (via FormData or a ref) and set a starting value with defaultValue. Simpler for basic forms, and React 19 form Actions (Day 7) work naturally with them.

4.6 Lifting state up

When two components need the same data, move the state to their closest common parent and pass it down. One owner, one truth.

4.7 Five principles for structuring state

  1. Group related state that always changes together (e.g. { x, y }).
  2. Avoid contradictions: one status: 'idle' | 'loading' | 'error' beats two booleans that can both be true.
  3. Avoid redundancy: if you can compute it from props or other state, compute it.
  4. Avoid duplication: store selectedId, not a copy of the selected object.
  5. Avoid deep nesting: flatten when updates become painful.

Interview corner

Why does console.log right after setState show the old value?

Because state is a snapshot for the current render. setState schedules a new render; the variable in the current closure never changes. The new value appears in the next render.

When do you use the functional updater setX(prev => ...)?

Whenever the next state depends on the previous one, especially with multiple updates in one event, or inside timers and async callbacks where the closure may be stale.

What is batching?

React combines several state updates into a single re-render. Since React 18 this is automatic everywhere: event handlers, timeouts, promises and native events.

Controlled vs uncontrolled components?

Controlled: value lives in React state, updated via onChange; good for live validation and dependent fields. Uncontrolled: value lives in the DOM, read on submit via refs or FormData; less code, fewer renders.

Why must state be updated immutably?

React detects change by reference comparison. Mutation keeps the same reference, so React may skip rendering, memoised children will not update, and features like time-travel debugging break.

What does "lifting state up" mean?

Moving state to the closest common ancestor of the components that need it, then passing the value and a setter down as props.

What happens if you call setState directly in the render body?

Each render schedules another render: an infinite loop. React stops it with "Too many re-renders".

Day 5 · The render cycle and effects

Week 1 · Foundations

About 4 hours. useEffect is the most misused hook in React. Today you learn when not to use it.

By the end of today you can

  • Write effects with correct dependencies and clean-ups.
  • Fetch data safely and recognise effects you do not need.

5.1 Trigger, render, commit

Think of it like

A restaurant. Trigger: a customer places an order (initial load, or a state change). Render: the kitchen prepares the dish (React calls your components to work out the new UI). Commit: the waiter puts the plate on the table (React updates the real DOM). Then the browser paints.

A component re-renders when:

  1. its own state changes;
  2. its parent re-renders (by default, all children re-render too);
  3. a context it reads changes.

"Props changed" is not a separate cause: props only change because the parent re-rendered. And a render does not necessarily touch the DOM; if the output is identical, the commit does nothing.

5.2 What an effect is for

An effect lets a component synchronise with something outside React: a timer, a browser API, a WebSocket, a non-React widget, the document title. It runs after the commit.

5.3 Clean-up

Common trap — "my effect runs twice!"

In development, StrictMode mounts, unmounts and re-mounts every component once. If your effect breaks because of that (double subscriptions, two intervals), your clean-up is missing. Fix the clean-up; do not remove StrictMode.

5.4 Fetching data safely

Without the abort, a slow response for user 1 could arrive after the fast response for user 2 and overwrite it. That is a race condition. In real apps you would usually reach for a data library (TanStack Query, SWR) or framework-level fetching (Next.js Server Components, Day 10), which handle caching, retries and races for you.

5.5 You might not need an effect

Interview corner

Why does my effect run twice in development?

StrictMode simulates unmount and re-mount to verify that clean-ups are correct. It only happens in development. A correct effect + clean-up pair behaves the same whether it runs once or twice.

useEffect vs useLayoutEffect?

Both run after the DOM is updated. useEffect runs after paint (non-blocking); useLayoutEffect runs before paint and blocks it. Use the layout version only to measure or adjust layout to avoid flicker.

What are common causes of an infinite effect loop?

Setting state inside an effect with no dependency array; a dependency that is a new object, array or function on every render; or an effect that sets the very state it depends on without a guard.

How do you avoid race conditions when fetching in an effect?

Abort the previous request in the clean-up with AbortController, or use an ignore flag set to true in clean-up and checked before setting state. Better still, use a data-fetching library or framework.

When does a component re-render?

When its state changes, its parent re-renders, or a context it consumes changes. Re-rendering is not the same as updating the DOM.

6.1 The Rules of Hooks

  1. Call hooks only at the top level of a component or custom hook: not inside conditions, loops or nested functions, and not after an early return.
  2. Call hooks only from React functions (components and custom hooks), never from plain utilities.
Think of it like

React stores each component's hook data in a row of numbered lockers. The first useState call gets locker 1, the second gets locker 2, every render. React does not know your variable names, only the call order. Skip a call conditionally and everyone opens the wrong locker.

6.3 useReducer: when state updates have rules

Think of it like

A bank. You do not walk into the vault and change your balance. You fill in a slip ("deposit 500") and hand it to the teller. The slip is an action, the teller is the reducer, and dispatch is handing over the slip. All the rules live in one place: the teller's desk.

A reducer must be pure: no fetching, no random ids, no mutation. That purity makes it trivially unit-testable: expect(cartReducer(state, action)).toEqual(expected).

Memory hook

Dispatch says what happened; the reducer decides how state changes. Name actions in the past tense: added, removed.

Prefer useReducer when several pieces of state change together, when the next state depends on complex rules, or when you want those rules testable in isolation. Prefer useState for simple, independent values.

6.4 Context: broadcasting without prop drilling

Think of it like

Prop drilling is passing a note hand-to-hand down a row of desks. Context is the college PA system: the provider makes an announcement, and anyone in the building who is listening (useContext) hears it directly.

Common trap — Context is not a free global store

When the provider's value changes, every component reading that context re-renders. A custom hook is a function whose name starts with use and which calls other hooks. Each component that calls it gets its own independent copy of the state inside.

Memory hook

Custom hooks share the recipe, not the meal. Two components calling useLocalStorage('x') have two separate states (even if they happen to read the same key at start).

Interview corner

Why can't hooks be called conditionally?

React identifies each hook by its call order within a component. Conditional calls change the order between renders, so state would be read from the wrong slot.

useRef vs useState?

Both persist across renders. Updating state triggers a re-render and is reflected on screen; mutating ref.current does not. Use refs for DOM access and mutable values that do not affect output.

When would you choose useReducer?

When multiple values change together, the update logic is complex or has many cases, or you want the transition logic pure and testable outside the component.

What are the drawbacks of Context?

All consumers re-render when the value changes; no built-in selector to subscribe to part of the value; a new object as value on every provider render causes extra renders. Mitigate by splitting contexts, memoising the value, or using a store library for hot global state.

Do two components using the same custom hook share state?

No. A custom hook is just a function; each call creates its own state. To share state, lift it up or put it in context or a store.

What was forwardRef for, and what changed in React 19?

Function components could not receive ref as a normal prop, so forwardRef was needed to pass a ref to an inner DOM node. In React 19, ref is available as a regular prop and forwardRef is no longer necessary for new code.

Explain SSR vs SSG vs ISR vs CSR.

Both wrap child routes. A layout persists across navigations between its children (state and DOM are kept); a template is re-created on every navigation, so its state and effects reset.

They depend on the incoming request. Making them promises lets Next.js prerender everything that does not depend on them and stream the rest, instead of forcing the whole page to wait.

9.1 Two kinds of component

In the App Router every component is a Server Component unless you say otherwise. Server Components run only on the server (at build or request time). Their code is never sent to the browser. They can be async and can read databases, files and secrets directly.

A Client Component is marked with 'use client' at the top of its file. It can use state, effects, event handlers and browser APIs.

Common trap — "Client Components only run in the browser"

False. Client Components are also pre-rendered to HTML on the server for the first load, then hydrated in the browser. "Client" means "its JavaScript is shipped to the browser and it becomes interactive there". That is why you still cannot touch window during render in a Client Component; use an effect.

9.3 The boundary rule

'use client' marks a boundary. That file, and everything it imports, becomes part of the client bundle. So a Client Component cannot import a Server Component. It can, however, receive one as children or another prop, because the server renders it first and passes the result in.

Think of it like

A Client Component is a picture frame with a hinge (it can open and close). The server paints the picture and slides it into the frame. The frame does not need to know how to paint.

9.4 What can cross the boundary?

Props passed from a Server Component to a Client Component travel over the network, so they must be serialisable: strings, numbers, booleans, null, plain objects and arrays, Date, Map, Set, promises, and JSX. Not allowed: ordinary functions, class instances, or anything with methods. The one kind of function you can pass is a Server Function ('use server', Day 11).

9.5 Keeping secrets on the server

Install it with npm install server-only. Environment variables without the NEXT_PUBLIC_ prefix are never inlined into client bundles (Day 12).

9.6 Context providers in a server world

Context needs a Client Component. Wrap your providers in one client file and use it in the root layout. The children passed through can still be Server Components.

9.7 What actually travels over the wire

Jargon buster — RSC payload

A compact, streamable description of the rendered Server Component tree: the output of Server Components, placeholders for where Client Components go plus references to their JS, and the props passed to them. On client-side navigation, Next.js fetches only this payload, not full HTML.

How do you avoid request waterfalls in Server Components?

Start independent requests together with Promise.all, move slow independent sections into their own components wrapped in Suspense so they fetch in parallel and stream independently, and preload data early when a later fetch depends on an earlier one.

Interview corner

What is a Server Action and how does it work under the hood?

An async function marked 'use server'. At build time Next.js gives it an ID and creates an endpoint. When the client invokes it (via a form or a call), the framework sends a POST with the serialised arguments; the server runs the function and returns the result plus, if you revalidated, an updated RSC payload in the same round trip.

Are Server Actions secure by default?

No. They are public endpoints. You must authenticate, authorise, and validate inputs inside each action. Next.js mitigates some CSRF risk with origin checks and uses unguessable IDs, but that is defence in depth, not access control.

How do you show a pending state for a form?

useActionState returns a pending flag; useFormStatus gives pending to any component inside the form (e.g. a submit button); useTransition gives isPending for actions called outside forms.

What is progressive enhancement?

The core feature works with plain HTML (a form that POSTs), and JavaScript improves it when available (no reload, pending states, optimistic updates). Form actions in Next.js submit even before hydration or without JavaScript.

Server Action vs Route Handler?

Actions are for mutations from your own app's UI, integrated with forms, revalidation and React transitions. Route Handlers are general HTTP endpoints for external clients, webhooks, or custom responses.

12.1 proxy.ts: code that runs before the route

In Next.js 16, middleware.ts was renamed proxy.ts to make its role clearer: it sits in front of your routes like a network proxy. It runs before a request is matched to a page, and can redirect, rewrite, or set headers and cookies.

Interview corner

What is middleware / proxy in Next.js, and what should it be used for?

Code that runs before a request reaches a route. Good for redirects, rewrites, locale detection, A/B bucketing, headers, and optimistic auth redirects. Not a replacement for authorisation in the data layer, and not the place for slow work such as database queries on every request.

Where should authentication checks happen?

Optimistically in the proxy for user experience, and authoritatively in a server-only Data Access Layer used by every page, Server Action and Route Handler that reads or writes protected data.

Why use httpOnly, secure and sameSite on a session cookie?

httpOnly hides the cookie from page JavaScript (an XSS attack cannot steal it). secure sends it only over HTTPS. sameSite=lax stops it being sent on most cross-site requests, reducing CSRF.

What does NEXT_PUBLIC_ do?

Variables with that prefix are inlined into the client bundle at build time, so they are public. Without it, variables are only available on the server.

How does Next.js help with SEO?

Server-rendered HTML that crawlers can read, the Metadata API (metadata, generateMetadata), generated Open Graph images, sitemap.ts and robots.ts, fast pages (Core Web Vitals affect ranking), and semantic HTML from you.

Why use next/image instead of <img>?

Automatic resizing and modern formats per device, lazy loading, reserved dimensions that prevent layout shift (CLS), and optional blur placeholders.

How would you test a Next.js application?

Why does Testing Library prefer getByRole?

It mirrors how users and assistive technologies find elements, makes tests resilient to refactors of markup and class names, and nudges you towards accessible HTML.

Explain Core Web Vitals.

LCP measures loading of the main content, INP measures responsiveness to interactions, CLS measures unexpected layout movement. Google uses them as a ranking signal, and they track real user experience.

They generate styles in the browser at runtime using React context, which Server Components cannot use, so every styled component must become a Client Component. Zero-runtime approaches (CSS Modules, Tailwind, compile-time CSS-in-JS) avoid that.
